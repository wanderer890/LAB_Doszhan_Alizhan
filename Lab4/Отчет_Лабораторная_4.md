## 1. Цель и постановка задачи
**Цель:** Научиться проектировать структурированный алгоритм и реализовывать его как пакет Python с высокой связностью модулей, слабым зацеплением и явно направленными зависимостями.
**Постановка задачи:** Создать пакет `university_rating`, который получает список студентов, проверяет оценки, вычисляет средний балл и статус допуска, после чего формирует отсортированный рейтинг.

## 2. Структура проекта
*   `__init__.py` — публичный интерфейс пакета.
*   `validation.py` — проверка типов, полей и диапазонов.
*   `calculations.py` — расчёт среднего значения и статуса студента.
*   `rating.py` — формирование и сортировка рейтинга.
*   `report.py` — преобразование результатов в текстовый вид.
*   `main.py` — демонстрационные данные и точка запуска.
*   `tests/test_rating.py` — проверка поведения публичных функций.

## 3. Результаты запуска основной программы
Запуск команды `python -m university_rating.main` выводит следующий результат:
Рейтинг группы
1. Amina: 86.33 допущен
2. Dias: 48.33 не допущен
3. Mira: - нет данных

## 4. Ответы на контрольные вопросы
1. **Какие три базовые управляющие структуры используются в структурном программировании?** Последовательность, выбор, повторение.
2. **Чем модуль отличается от пакета Python?** Модуль — файл Python с собственным пространством имён; пакет — каталог связанных модулей.
3. **Что означают высокая связность и слабое зацепление?** Связность — в одном модуле находятся функции одной предметной обязанности. Зацепление — модули знают друг о друге только через небольшой интерфейс.
4. **Почему расчётные функции не должны выполнять print?** Это позволяет использовать результат расчетов в любом другом интерфейсе (графическом, веб или в тестах).
5. **Для чего используется условие `__name__ == "__main__"`?** Условие предотвращает автоматический запуск `main` при импорте модуля.
6. **Почему `from module import *` ухудшает сопровождаемость?** Затрудняет отслеживание происхождения импортированных функций и может вызвать конфликты имен.
7. **Как возникает циклический импорт и как его устранить?** Возникает, когда два модуля импортируют друг друга. Устраняется путем переработки архитектуры и вынесения общих зависимостей в отдельный модуль.
8. **Почему `main` должен зависеть от предметных модулей, а не наоборот?** Низкоуровневые расчётные модули не должны знать о том, как запускается приложение или откуда берутся данные.
9. **Как проверить, что `build_rating` не изменяет входные записи?** Сравнить исходный список с его копией после выполнения функции с помощью метода тестов `assertEqual`.
10. **Какой модуль следует изменить при добавлении нового способа форматирования отчёта?** Модуль `report.py`.

## 5. Вывод
В результате выполнения работы была реализована тестируемая программа, разделенная на независимые модули. Зависимости направлены в одну сторону, что позволяет менять формат отчёта без изменения логики расчётов рейтинга.
